# 全実画面デザインシステム再監査

- 日付: 2026-10-09
- 対象: 既存67ページ定義、ソース上の追加/削除、共通242部品と呼び出し元。
- 目的: 旧デザインが残る画面数と確認不能数を分け、残作業と依存関係を確定する。
- UI実装や業務データ更新は行わない。既存アカウント/DBを読み取り、購入・送信・削除・seed・migration・DB初期化は行わない。

## 判定と受け入れ条件

1. 全page.tsxと台帳を突合し、画面本体/転送/仮実装を分類する。
2. 全画面の主要コンテナ、共通layout、CSS/部品の適用を追跡する。固定色だけでは未適用と判定しない。
3. 実NextルートをChromiumで1440/390px表示し、到達URL、見出し、エラー、横溢れ、背景/文字/見出し/操作を記録、画像を保存する。可能な実データを使い、動的ルートの架空IDは実表示監査に数えない。
4. 顧客/販売者/管理者の認証状態が用意できる場合、認証後の本体を再表示する。未入手なら全監査完了と呼ばず、未確認数・理由を記録する。fixture結果は実画面に加算しない。
5. 旧UI残存確認/本体適用確認/一部残存/認証・DB・データ不足で確認不能/転送/仮実装を明示する。ソース判定と実表示判定を分離する。
6. 画面別CSV/JSONと監査報告、優先順位付き残タスク、移行台帳/QA/採用計画の参照を同期する。文書リンク・67ID整合・check:playwrightを確認する。

## 検証方法

playwright.design.config.tsへroute suiteを追加、specはtests/browser/に置く。既存Next devコマンドを利用し、config/fixtureサーバーは新設しない。読み取り監査のためTDD Red実績は作らない。既存全体Jest/coverageの統計を変更しない。新たなコミットはこの監査では依頼されていないため行わない。
