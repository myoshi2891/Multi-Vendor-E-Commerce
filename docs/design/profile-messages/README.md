## スコープ境界

### ✅ スコープ内
- スレッド一覧の表示（過去にやり取りしたストア・販売者・サポートとの一覧）。
- チャット詳細UI（メッセージ履歴、テキスト送信フォーム）。
- メッセージのリアルタイム風更新（まずはシンプルなポーリングまたはSupabase/Pusher等の基盤を利用、本フェーズではNext.js Server Actions + DBポーリングを想定）。
- 新着メッセージの未読バッジ表示。

### ❌ スコープ外
- 画像やファイルの添付機能（テキストメッセージのみに制限し、画像は将来拡張）。
- ビデオ通話や音声通話機能。
- WebSocketサーバーの独自立ち上げ（Vercel等のサーバーレス環境を考慮し、Pusher等の外部サービスかHTTPポーリングで対応する）。

## 設計の核心判断

| # | 判断 | 要点 |
| --- | --- | --- |
| 判断1 | **ポーリングによるリアルタイム性の確保** | インフラの複雑性を避けるため、初版では3〜5秒間隔のポーリング（SWR/React Query 等または `useActionState` + `setInterval`）による簡易リアルタイム化を採用。 |
| 判断2 | **スレッド指向データモデル** | `MessageThread`（スレッド）と `Message`（メッセージ個別）の2層モデルとし、ストア（販売者）と顧客の1対1チャットを管理。 |
| 判断3 | **認可制御** | 各スレッドの `customerId` または `storeOwnerId` に合致するユーザーのみがスレッドにアクセスできるよう、厳格に認可チェックを行う。 |
