# 顧客メッセージ機能 — 要件定義書 (requirements.md)

## 1. 機能要件 (Functional Requirements)

### F1: メッセージスレッド一覧
- **要件**: ユーザーは自分に関連する（自身が関わる取引の）メッセージスレッド一覧を時系列で閲覧できること。
- **受け入れ基準**:
  - 各スレッドには、相手先の店舗名（または販売者名）と最新のメッセージ、送信日時が表示されること。
  - 未読のメッセージがある場合、視覚的なインジケータ（バッジ等）が表示されること。

### F2: チャットメッセージ送受信
- **要件**: ユーザーは選択したスレッド内でメッセージを送受信できること。
- **受け入れ基準**:
  - テキスト入力フィールドに入力し、送信ボタンまたはEnterキー（Shift+Enterは改行）でメッセージが即時送信されること。
  - 空白のみのメッセージは送信できないこと。
  - 自身が送信したメッセージは右側、相手からのメッセージは左側に整理されて表示されること。

### F3: 簡易リアルタイム更新
- **要件**: 画面を開いている間、相手から届いた新規メッセージが自動で表示されること。
- **受け入れ基準**:
  - HTTPポーリング（数秒間隔）などの仕組みにより、ページ全体をリロードすることなく、新しいメッセージがチャット履歴の最下部に追加されること。

---

## 2. 非機能要件 (Non-Functional Requirements)

### N1: 認可とアクセス制御
- **セキュリティ要件**: 自分以外のユーザーやストア間のメッセージスレッドに直接URL（例: `/profile/messages?threadId=xxx`）を入力してアクセスした場合、403（Forbidden）エラーまたはダッシュボードへのリダイレクトが行われ、盗み見が防止されること (IDORガードの徹底)。

### N2: レスポンシブデザイン
- スマートフォン表示時は、スレッド一覧とチャット画面が切り替え式（またはスライド表示）になり、デスクトップ表示時は2ペイン（左側に一覧、右側に詳細）で表示されること。
