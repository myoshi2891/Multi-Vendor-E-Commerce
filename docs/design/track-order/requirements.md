# Track Order — 要件（requirements.md）

> 記法: EARS 風（`When/While/The system shall`）。受け入れ基準は `AC-TO<n>`。
> 設計は [design.md](./design.md)、実装手順は [tasks.md](./tasks.md)。

---

## 1. 機能要件

| ID       | 要件（EARS 風）                                                                                                                                                                               |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **TO-1** | 任意の訪問者が `/track-order` で注文番号とメールアドレスを入力し照会したとき、システムは両者が一致する注文の配送状況を表示しなければならない。                                                |
| **TO-2** | システムは注文全体のステータス（`orderStatus`）と決済ステータス（`paymentStatus`）を表示しなければならない。                                                                                  |
| **TO-3** | システムは注文グループ（店舗単位）ごとに配送サービス名・配送予定日数（min〜max）を表示しなければならない。                                                                                    |
| **TO-4** | システムは注文アイテム（バリアント単位）ごとの商品ステータス（`ProductStatus`）を表示しなければならない。                                                                                     |
| **TO-5** | When 注文番号が存在しない、または email が当該注文の所有者 email と一致しないとき、システムは**両ケースを区別しない汎用メッセージ**（"注文が見つかりませんでした。"）を返さなければならない。 |
| **TO-6** | When 入力が空・不正形式のとき、システムは Zod 検証で照会を拒否しフィールド別エラーを表示しなければならない。                                                                                  |

## 2. 受け入れ基準（AC）

| ID         | 受け入れ基準                                                                                                                                     | 検証方法                   |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------- |
| **AC-TO1** | `orderId` と `email`（`order.user.email` と大文字小文字無視で一致）を渡すと、order/group/item を含む追跡データが返る。                           | ユニット（Prisma モック）  |
| **AC-TO2** | email が一致しない場合、`null`／"not found" が返り、**注文データは漏れない**（IDOR スロー検証）。                                                | ユニット                   |
| **AC-TO3** | 存在しない `orderId` の場合も AC-TO2 と**同一の応答**（存在有無を漏らさない）。                                                                  | ユニット                   |
| **AC-TO4** | `db.order.findUnique` の `where` が `{ id: orderId }` で、email 照合は取得後にアプリ層で行う（または `where` に email 条件を内包し副作用なし）。 | ユニット（where 構造検証） |
| **AC-TO5** | フォームが描画され、未入力 submit でエラー表示・`trackOrder` 未呼び出し。                                                                        | コンポーネント（RTL）      |
| **AC-TO6** | 一致時、結果領域に order/group/item ステータスが描画される。                                                                                     | コンポーネント             |

> AC-TO2〜AC-TO4 は IDOR 3 階層（(a) スロー検証 / (b) where 構造検証 / (c) 副作用なし検証）に対応（[SECURITY_GAP_REPORT.md §5.2](../../testing/SECURITY_GAP_REPORT.md)）。

## 3. 非機能要件（NFR）

| ID                              | 内容                                                                                                                                               |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| **NFR-TO1**（セキュリティ）     | 注文 id の存在を列挙されないよう、不一致/不存在を同一応答にする。email はログ出力しない（PII）。                                                   |
| **NFR-TO2**（コード規約）       | `any` 禁止・`console.log` 禁止。server action は `src/queries/order.ts` に追加（`src/queries/` 集約）。Prisma は try/catch + 構造化ログ。          |
| **NFR-TO3**（金額精度）         | 表示で金額に触れる場合は `Decimal` を return 境界で `toNumber()`。中間集計で `number` 加算しない（[tech.md](../../../.claude/steering/tech.md)）。 |
| **NFR-TO4**（リエントランシー） | 照会ボタンは `useRef` で二重送信防止。                                                                                                             |
| **NFR-TO5**（TDD）              | [`.claude/rules/02-tdd-step-commit.md`](../../../.claude/rules/02-tdd-step-commit.md) 遵守。                                                       |

## 4. スコープ外

- 配送業者（ヤマト/FedEx 等）の外部トラッキング API 連携・追跡番号表示（[product.md スコープ外](../../../.claude/steering/product.md): サードパーティ配送キャリア連携）。
- レート制限・reCAPTCHA（総当たり防止は follow-up）。
- ログイン済みユーザー向けの注文一覧（既存 `/profile/orders` が担当）。
- 注文ステータスの変更（閲覧のみ。変更は seller/admin ダッシュボード）。
