# 03. 参照カテゴリタクソノミー — ブランド非依存・20部門

> 位置づけ: [拡張計画ドキュメント群](README.md)の第3章。統合元: Round 2 ブループリント §3。
> **タクソノミーは「初期値のシードデータ」であり、コードではない**（[01 §2](01-vision-and-principles.md)
> の構造/ポリシー分離）。ブランド確定時は本章の部門表に有効化列を追記する（[README 更新規約](README.md#更新規約)）。

---

## 1. 設計原則

1. **トップレベルは「部門（Department）」= 顧客のメンタルモデルの入口**。Amazon・楽天・Walmart の
   グローバル EC で共通して現れる部門を採用し、特定ブランドに寄せない
2. **深さは可変（実運用 3〜4 階層、上限は設けない）**。リーフノードにのみ商品を紐づける運用を
   推奨するが、スキーマとしては中間ノードへの紐づけも許す（移行期の互換のため — 柱①）
3. **タクソノミーはコードでなくシード**: `prisma/seed/` に参照タクソノミーを投入するシーダーを置き、
   ブランド確定時は有効化フラグ（またはシードの差し替え）で絞り込む
4. **属性セット（柱②）はカテゴリに紐づく**: 部門ごとに「この部門の商品はこの属性を持つ」を
   定義するのがファセット検索の前提

---

## 2. 参照トップレベル部門（20部門）

ブランド未定の初期値として、グローバル総合 EC で標準的な 20 部門を定義する。
各部門に 2〜3 階層目の例示と、支配的なバリアント軸・代表ファセットを付す
（現行スキーマのバリアント軸は Size/Color 固定 — B-2 — のため、「軸」列は柱②の要件になる）:

| # | 部門 | 2〜3階層目の例 | 支配的バリアント軸 | 代表ファセット属性 |
|---|---|---|---|---|
| 1 | 家電・カメラ | テレビ > 有機EL / カメラ > レンズ > 単焦点 | 容量・型番 | 画面サイズ, 解像度, 接続規格 |
| 2 | パソコン・周辺機器 | ノートPC / キーボード > メカニカル | 構成(RAM/SSD) | CPU, メモリ, OS |
| 3 | スマートフォン・アクセサリ | 本体 / ケース > 手帳型 | 容量・色 | 対応機種, 通信規格 |
| 4 | ファッション（婦人・紳士・子供） | 婦人 > ワンピース / 紳士 > シャツ | **サイズ・色**（現行軸そのまま） | 素材, 丈, 柄, シーズン |
| 5 | シューズ・バッグ | スニーカー / トート | サイズ・色 | 素材, ヒール高, 防水 |
| 6 | ジュエリー・腕時計 | リング / 機械式時計 | サイズ(号数)・素材 | 素材, 石, 駆動方式 |
| 7 | ビューティー・コスメ | スキンケア > 化粧水 / ヘアケア | 容量・色番 | 肌質, 香り, SPF |
| 8 | ヘルスケア・医薬品(OTC) | サプリメント / 衛生用品 | 容量・個数 | 成分, 対象年齢 |
| 9 | 食品・飲料 | コーヒー > 豆 / 菓子 | 内容量・個数 | 産地, アレルゲン, 賞味期限区分 |
| 10 | ホーム・キッチン | 調理器具 > フライパン / 寝具 | サイズ・色 | 素材, 対応熱源, 食洗機可 |
| 11 | 家具・インテリア | ソファ / 照明 | サイズ・張地 | 幅×奥行×高さ, 組立要否 |
| 12 | DIY・工具・ガーデン | 電動工具 / 園芸用品 | 電圧・サイズ | 電源方式, 対応径 |
| 13 | スポーツ・アウトドア | キャンプ > テント / 自転車 | サイズ・色 | 収容人数, 耐水圧, 重量 |
| 14 | おもちゃ・ホビー | ボードゲーム / プラモデル | —（単一SKU多め） | 対象年齢, プレイ人数, スケール |
| 15 | 本・雑誌・メディア | 書籍 > 技術書 / 音楽 | 判型・フォーマット | 著者, 出版社, 発売日, 言語 |
| 16 | ゲーム | 本体 / ソフト | エディション | 対応機種, CERO, ジャンル |
| 17 | ベビー・マタニティ | ベビーカー / おむつ | サイズ・個数 | 対象月齢, 安全基準 |
| 18 | ペット用品 | ドッグフード / トイレ用品 | 内容量・サイズ | 対象動物, ライフステージ |
| 19 | 自動車・バイク用品 | タイヤ / カー用品 | サイズ(規格) | 適合車種, 規格(例:205/55R16) |
| 20 | 文具・オフィス | 筆記具 / 収納 | 色・個数 | 規格(A4等), インク色 |

### 読み方

- **4〜6（ファッション系）は現行の Size/Color 軸がそのまま効く = 現状の実装が最も得意な領域**。
  逆に 1〜3・15・19 は「容量」「判型」「規格」という第3の軸/属性が必須で、B-2 の解消（柱②）
  なしには正しく扱えない
- **8・9・17 は法規・安全基準の表示義務が絡む**ため、属性の必須化（カテゴリ別必須属性 — 柱②の
  中心機能）が単なる UX でなくコンプライアンス要件になる
- ブランド特化に転じる例: **ラグジュアリー寄せ** → 4/5/6/7 のみ有効化 + 属性「素材/原産国」を必須化。
  **テック寄せ** → 1/2/3/16 のみ有効化

## 3. タクソノミー運用ルール（シード設計の要件）

- ノードには URL の正規キーである `url`（既存 `Category.url @unique` を継承）、表示順 `sortOrder`
  （現状の `updatedAt desc` 順の置き換え）、`featured`（既存踏襲）、**有効化フラグ**を持たせる
- **リーフ以外への商品紐づけは新規では禁止**（移行期の既存データのみ許容 — 柱①の移行戦略）
- カテゴリ削除はハード delete（現行 `src/queries/category.ts:181` の `deleteCategory`）から
  「**無効化 + 商品の付け替え先指定**」へ改める（Amazon の browse node 廃止運用と同じ発想）

## 4. サイト構成への対応 — ナビゲーションと URL の骨組み

「どのような構成で扱うか」を、部門タクソノミーとストアフロントの面の対応として定義する。
現行のルート構成（`src/app/(store)/`）を土台に、**面は増やさず深さを増やす**方針:

| 面 | 現行 | 拡張後の骨組み |
|---|---|---|
| **部門入口** | ヘッダーのカテゴリリスト（2階層固定） | 部門メガメニュー: 部門（20）→ 2階層目までを表示し、以深はカテゴリページ側で展開 |
| **カテゴリブラウズ** | `/browse?category=…&subCategory=…`（クエリパラメータ・2階層） | `/browse?category=<leaf-url>` を維持しつつ、ツリー化（柱①）後は**パンくず＝祖先チェーン**（部門 > 中間 > リーフ）を表示。`url` は正規キーとして `@unique` を維持し、既存 URL は後方互換（柱①の決定事項） |
| **絞り込み** | サイズ・色・価格等の固定フィルタ | カテゴリ別ファセット（柱②③）: リーフカテゴリの属性定義から動的に生成 |
| **検索** | `/browse?search=…`（tsvector, name+description のみ） | 検索とブラウズの2系統を統合（柱③）。ファセット・価格ソート込み |
| **商品ページ** | `/product/[slug]` | 不変。構造化属性（柱②）の仕様表示と関連商品（柱⑤）が加わる |
| **回遊** | なし（`relatedProducts: []`） | 「関連商品」「一緒に購入」枠（柱⑤）— 単品ページの行き止まり解消 |

原則: **URL 契約（`/browse` + クエリパラメータ、`/product/[slug]`）は変えない**。
タクソノミーの深化はパンくず・メニュー・ファセットという「面の中身」に現れ、
ルーティング構造そのものはブランド確定後も安定させる。
