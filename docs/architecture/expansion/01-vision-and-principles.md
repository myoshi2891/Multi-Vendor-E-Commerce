## 1. 何を目指すか — 「Amazon 級」= 6つの構造的性質

本計画で「Amazon 級の世界トップクラス EC サイト」とは、GMV や品揃えの**規模**ではなく、
次の**構造的性質**を備えたマーケットプレイスを指す:

| # | 構造的性質 | 意味 |
|---|---|---|
| 1 | **カテゴリ横断性** | 家電もファッションも食品も、同一のカタログ基盤で破綻なく扱える |
| 2 | **発見性** | 数十万 SKU でも顧客が「探せる・絞れる・出会える」（検索 / ファセット / レコメンド） |
| 3 | **セルフサービスな販売者体験** | 出店から出品までがガバナンス（審査）付きで自走する |
| 4 | **運営コストの逓減** | カタログが増えても ADMIN の手作業が線形に増えない |
| 5 | **取引後の信頼ループ** | 買った後（返品・レビュー・問い合わせ）の体験が構造化されており、顧客と販売者の双方に「次も使う」理由を与える（Amazon の返品体験・レビューエコシステムに相当） |
| 6 | **プラットフォームの自己調整力** | 販売者の品質が計測され、閾値ポリシーで自動的に措置・販促・露出が調整される（Account Health / セールイベント運営に相当） |

性質 1〜4 は「カタログ基盤と発見性」（何を・どう売るか）、5〜6 は「運用・信頼・成長」
（売った後・信頼の維持・販促）に対応し、[04. アーキテクチャ10本柱](04-architecture-pillars.md)の
①〜⑤ / ⑥〜⑩ がそれぞれを土台化する。

## 2. ブランディング未定 → 「構造優先」の設計原則

ブランドの方向性（総合モール型か、特化型か、ラグジュアリー寄りか）は**未定**である。
したがって本計画のすべての章は次の原則で書かれている:

1. **構造（スキーマ・クエリ・ワークフロー）はブランド非依存に設計する。**
   カテゴリツリーの深さ・属性の種類・審査の厳しさは、すべて**データとして差し替え可能**にする
2. **コンテンツ（タクソノミーの中身・属性定義・審査ポリシー）はシードデータとして提供する。**
   [03. 参照タクソノミー](03-category-taxonomy.md)は「初期値」であり、ブランド確定時に
   絞り込み・入れ替えを行う前提
3. **特化型ブランドに転じる場合は参照タクソノミーの部分集合を有効化するだけで済む**構造にする
   （例: ラグジュアリー特化なら「ファッション/ジュエリー&時計/ビューティー」のみ有効化）

### 構造とポリシーの分離マップ

「何がコード（構造）で、何がデータ（ポリシー）か」の線引きが本計画の背骨である:

| 領域 | 構造（スキーマ・状態機械・seam） | ポリシー（データ/シードで差し替え） |
|---|---|---|
| カテゴリ | N 階層ツリー・slug・有効化フラグ | タクソノミーの中身（20部門の取捨選択） |
| 商品属性 | 属性定義/属性値の2層モデル | カテゴリ別の属性セット・必須/任意 |
| 出品審査 | 商品公開状態の状態機械 | 審査モード（全商品/新規販売者のみ/事後） |
| 返品 RMA | RMA エンティティ + 状態機械 | 返品可能期間・可否条件・自動承認閾値 |
| レビュー | モデレーション状態 + 通報 + 集計 | 審査モード（事前/事後/無審査）・表示閾値 |
| 販促 | キャンペーン エンティティ + 価格履歴 | イベント種別・割引率上限・開催頻度 |
| 通知 | Notification テーブル + チャネル seam | イベント→通知マッピング・チャネル選択 |
| セラー品質 | 事実タイムスタンプ + メトリクス集約 | 措置閾値（警告/DISABLED/BANNED の基準） |

この分離が守られている限り、**ブランド確定はポリシー値の変更に閉じ、構造（フェーズ計画・
スキーマ・ワークフロー）は不変**である — 検算は [05. ロードマップ](05-phased-roadmap.md) §4。
